# Data Schema

All files in [data/](../data) are generated by an internal build script from one internal source catalog. Do not edit them by hand. Data and charts are licensed CC BY 4.0 ([LICENSE-DATA](../LICENSE-DATA)).

| File | Format | What it holds |
|---|---|---|
| [catalog.csv](../data/catalog.csv) | CSV, UTF-8, header row | One row per load measurement. Empty cell means not recorded. |
| [catalog.json](../data/catalog.json) | JSON | `{"schema": "historical-catalog-v1", "rows": [...]}`. Same rows and fields as the CSV; empty cells are `null`. |
| [summary.json](../data/summary.json) | JSON | Release, counts, date range, exclusion counts, column list, chart grouping fields and the source SHA-256. |
| [charts.json](../data/charts.json) | JSON | `{"schema": "historical-charts-v1", "charts": [...]}`. One entry per chart in [RESULTS.md](RESULTS.md). |

## catalog.csv and catalog.json

Numbers are kept exactly as recorded (not re-rounded) and stored as strings; parse numeric columns yourself. Model, GPU and configuration labels are normalized to one public name each.

| Column | Type | Meaning |
|---|---|---|
| `row_id` | integer | Row number, 1 to N in this release. Cite a single result by `row_id` and release. |
| `model` | text | Model name without the organization prefix, for example `Qwen3.8-27B`. Checkpoints published under their own name (`-FP8`, `-NVFP4`) are separate models; otherwise the precision is in `precision`. |
| `config` | text | Serving configuration (see the glossary below), or `Dedicated Endpoint (managed)` for Spheron Dedicated Endpoints. |
| `date` | YYYY-MM-DD | Day the measurement was recorded. |
| `area` | text | Study the row belongs to: `dedicated-endpoints`, `multi-gpu-tuning`, `large-model-validation` or `single-node-sweeps`. See [PROVENANCE.md](PROVENANCE.md#areas). |
| `params_b` | number | Model parameters in billions, when recorded. |
| `precision` | text | Weight, activation and KV cache precision. |
| `engine` | text | `vLLM` or `SGLang`, with `+ MTP` when multi-token prediction is on. |
| `engine_version` | text | Engine version. `managed default` is the Dedicated Endpoints default on that day; the exact version was not recorded for these runs. |
| `gpu` | text | GPU model, one name per part: `H100 SXM`, `H200`, `B200`, `B300`, `RTX PRO 6000`, `L40S` and so on. |
| `gpu_count` | integer | GPUs serving the model. |
| `workload` | text | Load shape: prompt policy, approximate lengths, time per concurrency level, warm-up. |
| `input_tokens` | integer | Input tokens per request, when recorded. |
| `output_tokens` | integer | Output tokens per request (or the cap), when recorded. |
| `concurrency` | integer | Requests in flight at once for this level. |
| `output_tok_s` | number | Output (generated) tokens per second summed across all concurrent requests. |
| `total_tok_s` | number | Input plus output tokens per second. Not comparable with `output_tok_s`. |
| `req_s` | number | Completed requests per second. |
| `ttft_p50_ms`, `ttft_p95_ms` | number | Time to first token, median and 95th percentile, in milliseconds, measured at the client. |
| `tpot_p50_ms` | number | Median time per output token after the first, in milliseconds. |
| `itl_p50_ms` | number | Median inter-token latency, in milliseconds. |

## Glossary

| Term | Meaning |
|---|---|
| TP4, TP8 | Tensor parallelism across 4 or 8 GPUs: each layer is split over the GPUs. |
| DP8, TP4 x DP2 | Data parallelism: independent copies of the model, each serving part of the traffic. |
| EP8, expert parallel | Mixture-of-experts layers spread so that each GPU holds different experts. |
| DP-attention | SGLang mode that runs attention data-parallel while experts stay expert-parallel. |
| MTP, EAGLE 3/1/4 | Multi-token prediction (speculative decoding). The numbers are speculative steps / top-k / draft tokens. |
| n-gram speculation | Speculative decoding that drafts tokens by matching earlier text in the prompt. |
| FP8 KV, hierarchical cache | KV cache stored in FP8; KV cache that spills from GPU memory to host memory. |
| NVFP4, MXFP4, MXFP8 | 4-bit and 8-bit floating-point formats for Blackwell GPUs. |
| plain | The engine's default flags for that parallelism, with no extra tuning. |
| tuned settings | The engine flags chosen after the tuning sweeps. |
| revision 3431dde | The Hugging Face commit of the checkpoint that was served. |
| cached-token reporting on | SGLang reports how many prompt tokens came from the prefix cache. |
| same prompt for every request | The Dedicated Endpoints workload: 220 input and 256 output tokens, one fixed prompt, so prefix caching can help. |
| per copy | Load sent to one model copy when two copies share a node. |
| TTFT, TPOT, ITL | Time to first token, time per output token, inter-token latency. |

## summary.json

| Key | Meaning |
|---|---|
| `release` | Release version, for example `2026.11.23`. |
| `rows`, `source_rows` | Published rows, and records in the private source. |
| `excluded_rows` | Records left out, by reason: `damaged-or-invalid`, `overloaded`, `warm-up-level`, `duplicate`, `incomplete`, `out-of-scope`. See [PROVENANCE.md](PROVENANCE.md#what-was-left-out). |
| `source_catalog_sha256` | SHA-256 of the private source catalog this release was built from. |
| `models`, `gpu_models` | Distinct models and GPU models. |
| `chart_groups`, `chart_eligible_rows`, `plotted_rows` | Number of charts, rows that could be charted, rows actually charted. |
| `date_min`, `date_max` | Date range of the published rows. |
| `columns`, `group_fields` | Columns in the CSV and JSON, and the fields that define one chart context. |
| `areas` | Area labels present in this release. |

## charts.json

Each entry: `asset` (SVG path), `group` (the twelve fields held fixed: model, config, engine, engine_version, gpu, gpu_count, area, workload, precision, input_tokens, output_tokens, date) and `points` (`row_id`, `concurrency`, `output_tok_s` for every plotted run). A row is charted when its concurrency is a positive integer, output throughput is a finite non-negative number, and its context has at least two concurrency levels.

## benchmark.py output (`spheron-sse-run-v1`)

New runs from [benchmark.py](../benchmark.py) are written as one JSON file per run, kept separate from the historical catalog.

| Key | Meaning |
|---|---|
| `schema`, `created_utc`, `model` | Schema id, UTC start time, model name sent to the endpoint. |
| `method`, `runtime`, `temperature`, `prompt_policy` | Always fixed-count closed loop, Python stdlib, temperature 0, unique prompts. |
| `input_words`, `max_tokens`, `requests_per_level`, `warmup_requests_per_level`, `socket_timeout_s` | Run settings from the command line. |
| `endpoint_recorded` | Always `false`: the endpoint URL is never written. |
| `levels[]` | One entry per concurrency level: `concurrency`, `attempted_requests`, `successful_requests`, `errors`, `warmup_errors`, `wall_s`, `prompt_tokens`, `completion_tokens`, `usage_prompt_requests`, `usage_completion_requests`, `output_tok_s`, `total_tok_s`, `req_s`, `ttft_samples`, `ttft_p50_ms`, `ttft_p95_ms`, `tpot_estimate_p50_ms`, and `samples[]` with per-request `ok`, `error`, `ttft_ms`, `elapsed_s`, `prompt_tokens`, `completion_tokens`, `tpot_estimate_ms`, `content_chunks`. |

Token counts come only from the API `usage` field. If any successful request lacks usage, the level's token totals and token rates are `null`.
